# /bam-generate-notebook

Generate a Jupyter provisioning notebook from a reviewed gap report.

## Usage

```
/bam-generate-notebook <prd-path>
```

Example:
```
/bam-generate-notebook BAM_PRD_Workflow_FB72.md
```

## Pre-requisites

- [ ] `/bam-analyze-prd <prd-path>` has been run.
- [ ] `generated/<prd-stem>/gap-report.md` has been reviewed and approved by a human.
- [ ] (Recommended) `/bam-generate-types <prd-path>` has been run and the resulting masterdata PR is open or merged — the notebook references types that must exist in openBIS before any `new_sample(type=...)` call succeeds.

## What this command does

Invokes the **`openbis-notebook-generator`** agent:
- Input: `generated/<prd-stem>/requirements.json` + `generated/<prd-stem>/gap-report.md`
- Output: `notebooks/<prd-stem>_provisioning.ipynb`

The notebook is the **one-time setup path**: it provisions Space/Project/Collection + parent specimen Objects + ExperimentalStep children. For per-run data ingestion, cells 13–14 reference the parser package generated by `/bam-generate-parser`.

## Notebook contract (14 cells, MANDATORY)

The agent emits exactly 14 cells in a fixed order. Any deviation fails the regression scorer (`_score.md` §5):

| # | Type | Purpose |
|---|---|---|
| 1 | Markdown | Header (PRD path, openBIS + pyBIS versions, generated timestamp) |
| 2 | Code | Imports (`pybis`, `getpass`) |
| 3 | Markdown | ⚠ Fill-me-in checklist |
| 4 | Code | Config variables (URL, SPACE, PROJECT_CODE, COLLECTION_CODE) |
| 5 | Code | PAT bootstrap (first-run only — the only place `getpass.getpass` appears) |
| 6 | Code | Sanity check (`o.is_session_active()`) |
| 7 | Markdown | Reminder: push masterdata extension via CLI or PR before continuing |
| 8 | Code | Create Collection via `o.new_experiment(...)` |
| 9 | Code | Create parent specimen Object(s) (CREATE ObjectTypes from gap report) |
| 10 | Code | Create ExperimentalStep children (one block per CREATE ExperimentalStep) |
| 11 | Code | Dataset upload stubs |
| 12 | Code | `o.logout()` |
| 13 | Markdown | Two-path model explanation (notebook = setup, parser = ingestion) |
| 14 | Code | `run_parser(...)` usage stub with `# TODO` markers |

## After generation

### Validate the generated notebook

```bash
# nbformat 4.4 conformance + cell count
python -c "import nbformat; nb = nbformat.read(open('notebooks/<prd-stem>_provisioning.ipynb'), as_version=4); assert len(nb.cells) == 14, f'expected 14 cells, got {len(nb.cells)}'; print('OK — 14 cells, valid nbformat 4.4')"

# Exactly one credential prompt (Cell 5 PAT bootstrap)
grep -c "getpass.getpass" notebooks/<prd-stem>_provisioning.ipynb
# → must be exactly 1

# No forbidden pyBIS calls (no o.create_*, no o.new_collection())
grep -nE "o\.create_|o\.new_collection\(" notebooks/<prd-stem>_provisioning.ipynb
# → must return empty

# No hardcoded credentials
grep -nE "password\s*=\s*['\"]|token\s*=\s*['\"][A-Za-z0-9]" notebooks/<prd-stem>_provisioning.ipynb
# → must return empty (TOKEN is set from PAT bootstrap, never hardcoded)
```

### Next steps

1. Open the notebook in Jupyter / VSCode and fill in the four TODO placeholders in Cell 4 (URL, SPACE, PROJECT_CODE, COLLECTION_CODE).
2. **Before running**, ensure the masterdata extension is pushed to your openBIS instance:
   ```bash
   pip install -e ../bam-masterdata
   python -m bam_masterdata masterdata_sync --url $OPENBIS_URL --token <your-pat>
   ```
   Or wait until the `add-<prd-stem>-types` PR is merged into `BAMresearch/bam-masterdata` and the instance is updated.
3. Run cells 1–12 once to provision the hierarchy.
4. For per-run data ingestion, generate the parser scaffold next: `/bam-generate-parser <prd-path>`.

## Print after success

```
Generated: notebooks/<prd-stem>_provisioning.ipynb
  14 cells (mandated structure)
  PAT auth in Cell 5 only — no hardcoded credentials
  Cells 13–14 reference parser package for ongoing ingestion

Before running the notebook:
  [ ] Fill TODOs in Cell 4 (URL, SPACE, PROJECT_CODE, COLLECTION_CODE)
  [ ] Push masterdata extension to openBIS (see Cell 7)
  [ ] Verify EXTEND PRs (e.g., WELDING.WELD_TYPE additions) are merged

Next: /bam-generate-parser <prd-path>
```

## Anti-patterns

- Do NOT run this without reviewing the gap report first — the notebook references types whose names come from the CREATE/REUSE classification.
- Do NOT edit the generated notebook structurally (cell order/count) — re-run the generator if changes are needed. User-edited TODOs in Cell 4 / Cells 9–11 are expected and fine.
- Do NOT hardcode credentials anywhere in the notebook — the PAT bootstrap (Cell 5) is the only authentication path.
- Do NOT replace `o.new_experiment(...)` with `o.new_collection(...)` in Cell 8 — the latter is called internally by `run_parser()` and double-calling breaks idempotency (see PLAN.md §0.3).
